# XFrame iOS app — 設計文件

把 XFrame（X）與 ThreadsFrame（Threads）合成一個**只給自己用**的 iPhone app。
網頁版（`xframe.gariber.studio`、`threadsframe.gariber.studio`）與品牌網址都不變，
照常可以用。

---

## 為什麼要做

做這兩個工具的起點是：直接截圖不好看。網頁版能用，但在手機上有三個痛點：

1. **選版式與樣式要滑來滑去，不直觀。** 控制項排成一長串，選一項要捲回去看卡片。
2. **文字樣式還不夠好看。** 說不出具體哪裡，屬於主觀感受。
3. **影片卡片要等。** 錄製跟著真實時間跑，影片多長就等多久；影片比例不一時，
   文字與影片的呈現也不和諧。

Cloudflare 上近 30 天的數據（2026-10-28 查）顯示外部使用者幾乎沒有，所以這個 app
可以完全照使用者本人的習慣設計，不必為別人妥協。

## 使用情境

在 X 或 Threads 的 iOS app 裡看到一則貼文 → 按「分享」→ 選這個 app → 看到卡片
→ 依內容的氣質挑一種氛圍 → 用 iOS 分享選單把圖或影片送到 IG 限動。

主要去處是 **IG 限動**，次要是存下來傳給朋友。都經 iOS 分享選單，
不需要 Instagram 的 Stories URL scheme（也就不需要 Meta App ID）。

## 目標

- 一個 iPhone app，支援 **X 與 Threads**。
- 從 X / Threads app 的**分享選單**直接帶入貼文；也能手動貼連結。
- 以「**氛圍**」為主要選擇單位的樣式選擇器，卡片一直在畫面上。
- 影片卡片在**背景快速合成**，不跟著影片長度等待。
- 兩個平台**設計統一**：app 裡 X 與 Threads 用同一套卡片元件、紙張、樣式。
- app 與 XFrame 網頁版在同一個 repo、共用底層卡片程式；但這次的新東西**只進 app**。

### 網頁版這次維持現狀（使用者決定）

app 做出來一定還要調整，等 app 調整得差不多了，再把成果一起帶回網頁版。這次：

- `xframe.gariber.studio` 與 Chrome 擴充功能的行為、外觀、比例選項、樣式預設**完全不變**。
  氛圍選擇器、只輸出 9:16、字體與排版改善、新紙張，都放在 **app 專屬的一層**，
  不改動網頁版正在用的設定與預設。共用的 `Card` 若需要新能力，以「選項預設關閉」
  的方式加，網頁版不開。
- `threadsAdapter` **只在 app 的組建裡註冊**，網頁版與擴充功能的 adapter 註冊表不變，
  網頁版貼 Threads 連結的行為維持原樣。
- `threadsframe.gariber.studio`（`threadframe-web` repo）**不動**。只把它解析 Threads
  的邏輯移植進 xframe repo 的 `threadsAdapter`。

## 非目標

- **不做微博、小紅書。**（使用者明確排除）
- 不上 App Store、不做給別人用的設定、不做帳號系統。
- 不處理 Chrome 擴充功能與 Chrome 商店（擴充功能的程式碼仍在同一個 repo，
  不能被弄壞，但這次不為它加功能）。
- 不改兩個網址與品牌。

## 反目標（做出來但等於失敗的情況）

- **內文被截斷。** 這是最高指導原則，任何版面取捨都要讓它。
- **影片被放大或裁切**，導致畫面邊緣的資訊遺失。
- 卡片看起來不像 X / Threads 原本的貼文。
- 字體花俏、搶過內容。
- 網頁版因為這次的修改而壞掉或變樣。

## 已經決定的事

### 平台與功能範圍

X 與 Threads。兩邊現有的功能**全部保留**，都是使用者實際在用的：

- Threads：「原貼文＋某一則留言」、留言串接線、話題。
- X：引用推文、回覆時帶出父貼文、翻譯（貼入譯文＋「翻譯自◯文」）、隱私選項。

### 卡片版面：還原原平台的呈現

- 卡片照 X / Threads 自己的排法：Logo 一行、作者列、內文、媒體在內文下方、
  時間、分隔線、互動數據、品牌。這是已驗證過最和諧的排法（見 `design-qa.md`）。
- **輸出畫布固定 9:16**（1080×1920）。不再提供 1:1、4:5 等比例。
- 媒體（圖片、影片）**保持原始比例**，滿貼文卡寬度放置，**不放大、不裁切**。
- 貼文卡太高放不進 9:16 時，**整張貼文卡一起等比縮小**，周圍露出背景紙張。
  直影片＋長內文時會縮得比較小（示意約 58%），使用者明確表示可以接受，
  理由是社群影片通常內文不長。
- 曾考慮過「直影片鋪滿整張卡片、文字疊在底部漸層上」的版式，**已捨棄**：
  它違背「還原原平台呈現」，也可能讓內文不截斷變得難以做到。

### 選樣式的方式：氛圍

- 使用者挑樣式的理由是**配合內容的氣質**：嚴肅的用黑白／夜間，幽默的用活潑的紙張，
  文學味的用雜誌感。
- 主畫面：**卡片固定在上半部**，下方一排可以左右滑的**氛圍縮圖**，點一下卡片就換。
  不需要上下捲動。
- 每種氛圍是一組搭好的組合：背景紙張、底板顏色與透明度、留白、文字尺寸、字體。
- 選定氛圍後可以「換一張」，在同一氛圍內重新抽紙張（保留隨機產生的樂趣）。
- 細調（紙張、留白、文字尺寸、底板顏色、底板透明度）收在一個抽屜裡，需要時才拉出。
  這三類是使用者最常動的。
- 氛圍由使用者自己挑，不做自動判斷。
- **「幽默／活潑」目前沒有滿意的紙張**，需要新設計一組，屬於這次的新工作。
  做法（Claude 的判斷）：先做幾款候選放在瀏覽器分頁給使用者挑，選定後才進 app。
  使用者挑過才算完成。

### 文字樣式（Claude 的判斷）

「不夠好看」不只靠換字體解決。實作時把行距、字重、字距、中英文與 emoji 混排
各做幾個版本，用同一則真實貼文並排給使用者挑，再把挑中的結果定成規則。
只套用在 app。

### 從分享選單一步進 app（使用者決定）

- 在 X 或 Threads 的 iOS app 按「分享」→ 選這個 app → **直接跳進主 app**，
  連結已經帶入、卡片已經在產生，使用者只剩挑氛圍與細調、匯出。
  中間不出現確認框、不需要再點「開啟」或「產生」。
- 做法（Claude 的判斷）：分享延伸功能收到網址後立刻以自訂 URL scheme
  （例如 `xframe://card?url=…`）開啟主 app，主 app 依網址取文並顯示卡片。
  個人使用不上架，可以用 App Store 審核不允許的方式從延伸功能開啟主 app。
- 退路：若目前的 iOS 版本擋下從延伸功能開啟主 app，改成在延伸功能裡以全螢幕
  載入同一套編輯介面，使用者看到的流程一樣。
- 主 app 已經開著、正在編輯另一張卡片時，新分享進來的貼文取代目前那張。

### 字體

- 文學／雜誌感：**Hiragino Mincho ProN**（iOS 內建）。缺字時由系統補字，
  補字字型優先用宋體-繁（Songti TC）以維持筆觸接近。
- 其餘：**蘋方**（PingFang TC）。
- 不加其他花俏字體。內容是主體。

### 影片卡片

- 影片放在貼文卡裡、原始比例、可以播放，最後輸出整張 9:16 卡片的 MP4（H.264＋AAC）。
- 合成**不跟著真實時間跑**，在 iPhone 上用硬體編碼，目標是幾秒內完成 30 秒的影片。
- 聲音原封不動保留。

### 技術路線（Claude 的判斷，使用者未反對）

- **一份網頁程式，包成原生 iOS app**（Capacitor 或同類做法），不另外用 SwiftUI
  重寫卡片。理由：之後要把 app 的成果帶回網頁版，兩套卡片畫法會讓這件事做不到。
- 原生那一側負責網頁做不到的事：
  - **分享延伸功能（Share Extension）**：接收 X / Threads app 分享過來的連結。
  - **原生 HTTP 取文**：不受 CORS 限制，app 內可以直接以爬蟲 UA 向 Threads 取文，
    也直接抓 X。**app 不需要 Cloudflare worker**；worker 只留給網頁版。
  - **影片合成**：若網頁端的 WebCodecs 快路在 app 的 WKWebView 裡可靠，就沿用；
    不可靠的話改由原生 AVFoundation 合成（網頁端輸出「挖空影片位置的卡片圖＋影片矩形座標」，
    原生把影片放進那個矩形）。由實作時實測決定。
  - **iOS 分享選單**輸出圖片與影片。
- 個人使用：使用者是付費 Apple Developer，直接用 Xcode 裝到自己的 iPhone
  （環境已確認：Xcode 27.1、有效的 Apple Development 憑證）。之後可視需要走 TestFlight。

### 程式碼的基準

- 以 **`origin/source`**（`64baaad 紙張與樣式改成跟 ThreadsFrame 同一套`）為起點，
  開在分支 `feat/ios-app`。這個分支已經包含：
  - ThreadsFrame 的 14 款內建紙張＋紙庫 26 張（`src/render/papers.ts`）。
  - 樣式預設：純淨白、夜間、雜誌感、便條紙、大字報、柔霧、夕燒玻璃、極光玻璃
    （`src/render/styles.ts`）——這就是「氛圍」的現成雛形。
  - 影片：卡片內播放、媒體圖框跟著媒體比例、WebCodecs 快路
    （`src/render/video.ts`、`src/render/video-fast.ts`）。
  - 平台 Adapter 註冊表（`src/platforms/`），目前只有 `xAdapter`。
- 本機的 `source` 分支落後 `origin/source` 26 個 commit，不要以它為基準。
- ThreadsFrame 原始碼在 `~/Documents/Codex/2026-08-11/threadframe-web`
  （解析：`src/parse.ts`、取文：`src/fetchPost.ts`、繪製：`src/render.ts`、
  worker：`worker/src/index.js`，規格 `worker/API.md`）。Threads 的解析邏輯
  應移植成 `threadsAdapter`，卡片則改用 XFrame 的 `Card` 元件呈現。

## 留給實作者決定的事

- 氛圍要幾種、各自的名字與參數（以現有 8 個樣式預設為起點，配合「嚴肅／幽默／文學」
  三種使用情境整理；「幽默」需新設計紙張）。
- 縮圖列與細調抽屜的具體互動與動畫。
- Capacitor 或其他包裝方式的選擇、iOS 最低版本。
- 影片合成走 WebCodecs 還是 AVFoundation（實測決定）。
- Apple Translation 預填譯文：加分項目，可做可不做。

## 驗收

- 從 X app 與 Threads app 各分享一則貼文進來：選了這個 app 之後直接進到主 app，
  卡片已經產生，中間不需要任何額外點擊。
- 文字貼文、圖片貼文、橫影片、直影片、方形影片、引用推文、Threads 原貼文＋留言，
  都輸出 9:16、內文完整、媒體不裁不放大。
- 30 秒影片的匯出時間明顯短於 30 秒。
- 在氛圍縮圖之間切換不需要上下捲動。
- 匯出的圖片與影片能從 iOS 分享選單直接發到 IG 限動。
- 網頁版 `npm test` 全數通過，`npm run build:web` 的產出與這次修改前行為一致
  （比例選項、樣式預設、只支援 X 都不變）。
- 擴充功能 `npm run build` 仍能建置。
